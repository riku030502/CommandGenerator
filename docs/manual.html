GPSR コマンドジェネレータ

公式ジェネレータ (RoboCupAtHome/CommandGenerator) を、ブラウザ GUI と 2026 世界大会 (Incheon) の公式アリーナデータごと、すぐ動く形にまとめたセットです。 導入・データの作り方・本番運用・つまずきどころをこの 1 枚にまとめています。

Python 3.12 (uv が自動導入) UI NiceGUI 3.16 アリーナデータ Incheon 2026 動作確認 Ubuntu 22.04 インストール後は オフライン可
./setup.sh 別の PC ではまずこれ。uv・仮想環境・上流ソース・アリーナデータまで全部そろえます。
./run_gpsr_ui.sh GUI 起動。ブラウザで http://localhost:8080 を開きます。
./run_cli.sh テキスト版。QR コード生成と EGPSR セットアップはこちら。
./run_tests.sh 動作確認。データ検証と GUI の自動操作テストが走ります。
tools/check_llm.py その PC で使える LLM を探して疎通テスト。Rephrase を使うなら最初にこれ。

01

動作環境

項目内容
OSLinux (Ubuntu 22.04 で確認)。macOS / WSL も同手順で動きます
Python3.12 以上が必須。setup.sh が uv 経由で用意するので、PC 側に無くても構いません
その他git / curl / ブラウザ
ネット導入時のみ必要。導入後はオフラインで動きます (LLM 言い換えを使う場合を除く)
なぜ 3.12 なのか

上流の llm.py が Python 3.12 で追加された f-string 記法を使っており、3.11 以下では SyntaxError で落ちます。Ubuntu 22.04 の標準は 3.10 なので、必ず .venv 経由で起動してください。

02

別の PC への導入

A. ゼロから入れる (推奨)

setup.sh / run_*.sh / tools/ / tests/ / requirements.lock.txt を新しい PC にコピーして、 

cd <コピー先のフォルダ>
./setup.sh

これだけで次がすべて自動実行されます。

  1. uv が無ければ ~/.local/bin に導入
  2. 上流の CommandGenerator と Incheon2026 (2026 世界大会の公式データ) を clone (動作確認済みコミットに固定)
  3. .venv/ に Python 3.12 環境を作り、固定バージョンで依存を導入
  4. Incheon2026 から data/ を作成し、後述のフォーマット不備を自動修正
  5. データを検証してサンプルコマンドを 3 個表示

最後に PROBLEMS: none と == done が出れば成功です。

上流の最新版を使うなら ./setup.sh --latest、テストも入れるなら ./setup.sh --with-tests。何度実行しても安全で、既存の data/ は上書きしません。

別の大会のデータを使う場合は --competition= で指定します。 RoboCup@Home は大会ごとに github.com/RoboCupAtHome/<大会名> を公開しています。 

./setup.sh --competition=GermanOpen2026
./setup.sh --competition=Salvador2025          # 2025 世界大会 (練習用)
./setup.sh --competition=CompetitionTemplate   # 中身が汎用の空テンプレート

data/ を作り直すときは rm -rf data してから ./setup.sh です。

B. フォルダごと持っていく

USB などでコピーする場合、.venv/ には絶対パスが埋め込まれているため そのままでは動きません。コピー先で次を実行してください。 

./setup.sh --recreate    # .venv を作り直す。data/ と llm.conf はそのまま

CommandGenerator/ と Incheon2026/ が既にあれば clone は走らず、 依存パッケージのダウンロードだけがネットを使います。会場で完全オフラインにしたいなら、 本番で使う PC 上で事前に一度 ./setup.sh を通しておいてください。

C. uv を使わず手動で

git clone https://github.com/RoboCupAtHome/CommandGenerator.git
git clone https://github.com/RoboCupAtHome/Incheon2026.git
python3.12 -m venv .venv
./.venv/bin/pip install -r requirements.lock.txt
./.venv/bin/pip install -e ./CommandGenerator --no-deps
cp -r Incheon2026 data && rm -rf data/.git data/.gitmodules
python3 tools/fix_data_format.py data
03

起動する

GUI

./run_gpsr_ui.sh

起動すると待ち受け URL が表示されます。

NiceGUI ready to go on http://localhost:8080, http://192.168.0.104:8080, ...

ブラウザで http://localhost:8080 を開きます。表示された LAN の URL を使えば 同じネットワークのタブレットやサブ PC からも開けます。審判用の大画面に出すときに便利です。 

./run_gpsr_ui.sh --ui-port 9000          # 8080 が埋まっているとき
./run_gpsr_ui.sh -d /path/to/other/data  # 別のアリーナデータ
./run_gpsr_ui.sh --ui-show               # 起動時にブラウザを開く

停止は Ctrl+C です。

CLI (テキスト版)

./run_cli.sh

数字を入力して Enter で生成します。

入力内容
1任意のコマンド
2物体操作を含まないコマンド (人に関するタスク)
3物体操作を含むコマンド
43 個まとめて生成
5EGPSR セットアップ生成。個数を聞かれ、番号入力で個別に振り直し、r で全部振り直し
0直前のコマンドを QR コード画像で表示
q終了
 
./run_cli.sh -p              # 読み込まれたデータを一覧表示
./run_cli.sh -g > out.txt    # 5000 個生成してデータの不備を洗い出す
QR コードについて

0 は PIL が画像ビューアを起動します。デスクトップ環境の無い PC (SSH 越しなど) では表示できません。

04

GUI の使い方

生成画面

部品役割
#生成する個数 (1〜5)。既定は 3
Generate GPSR Commands指定個数を生成。1 個目は「人」系、2 個目は「物体」系、3 個目以降は任意カテゴリで、最後にシャッフルされます
Rephrase ALL全コマンドを LLM で言い換え (LLM 設定が必要)
New Commandそのカードだけ、同じカテゴリで作り直す
Rephraseそのコマンドだけ言い換える
Lock & Show内容を確定し、提示用画面へ切り替える

生成中・言い換え中はボタンが自動的に無効化されます。

提示画面

  • 上部のコマンドボタンを押すと、そのコマンドが下に大きく表示されます。
  • Text size スライダー (32〜254 px) で文字サイズを調整。会場の距離に合わせてください。
  • Phrasing 0 / 1 / 2 タブで言い換え候補を切り替えられます。
  • Lock & Show をもう一度押すと生成画面に戻ります。
競技記録が残ります

Lock & Show を押した瞬間に、その回のコマンドと言い換えがすべて ~/gpsr-ui.log に追記されます。競技後の確認や抗議対応に使えるので、大会中はこのファイルを消さないでください。

05

アリーナデータの入れ方

data/ には 2026 世界大会 (Incheon) の公式データが入っています。練習用に自分たちのアリーナへ書き換えることもできます。ジェネレータが読むのは次の 4 ファイルだけです。

data/
├── names/names.md 人の名前
├── maps/room_names.md 部屋
├── maps/location_names.md 家具・設置場所とカテゴリ
└── objects/objects.md 物体とそのクラス

objects/known_objects/ の画像や maps/arena.png はジェネレータでは使いませんが、 チーム内資料としてテンプレートの形式のまま置いておくと便利です。

names/names.md

## Names
| Names |
| ------------ |
| Adel |
| Angel |

英字 1 単語のみです。スペース・ハイフン・数字を含む名前 (Mary Jane, Anne-Marie, Taro3) は エラーにならず黙って無視されます。

maps/room_names.md

## Rooms
| Name |
| ------------ |
| kitchen |
| living room |

英字 1〜2 単語まで。3 単語以上 (big living room) やハイフン入りは無視されます。

maps/location_names.md

## Locations
| Number | Name  | Object Category |
| ------------ | ----------- | ----------- |
| 1 | laundry table (p) | fabrics |
| 2 | washing machine (p) | |
| 10 | refrigerator | |
  • (p) を付けると「物を置ける場所 (placement location)」になります。
  • Object Category はその家具が既定の置き場所になっている物体クラス。objects.md のクラス名 (複数形) と綴りを合わせます。空欄で構いません。
  • 名前に使えるのは英字とスペースだけ。数字やハイフン (table 2, side-table) を入れると、その行だけでなく前後の行まで巻き込んで読み飛ばされます。
最重要 — 行末のパイプ

上流のパーサは 3 列目の後ろにも | があることを前提にしています。 | 1 | bed (p) | のように行末の | が 1 本足りない行が混ざると、 その行だけでなく前後の行まで巻き込んで読み飛ばされ、警告も一切出ません。 必ずすべての行を | 番号 | 名前 | カテゴリ | の形にしてください。 

python3 tools/fix_data_format.py data

公式 2026 データにあった不備 (data/ では修正済み)

Incheon2026 をそのまま読ませると問題が出たので、data/ を作る際に自動で直しています。 Incheon2026/ の方は公式のまま残してあるので、差分を見たいときはそちらと比べてください。

  1. 全 20 行で行末の | が無い — fix_data_format.py が補完します。
  2. 13 行目で名前とカテゴリの間の | が抜けている — 公式ファイルはこうなっています。 
    | 13 | cooking table (p) cleaning supplies |
    このままだと家具名が cooking table cleaning supplies という 1 個の場所として読まれます。 (p) は必ず名前の終わりなので、そこで分割して直しています。 
    | 13 | cooking table (p) | cleaning supplies |
  3. 8 行目のカテゴリが foods — objects.md のクラス名は food なので綴りが合いません。これは未修正です。GPSR の生成には影響しない (Storing Groceries 用の情報) ため公式のままにし、check_data.py が WARNING として毎回知らせます。

objects/objects.md

# Class drinks (drink)

| Objectname               |  Image                   |
:-------------------------:|:-------------------------:
| coke | ![](known_objects/drinks!drink/coke.jpeg) |
| red_bull | ![](known_objects/drinks!drink/red_bull.jpeg) |
  • 見出しは # Class 複数形 (単数形) の形式。生成文中で drinks / a drink と使い分けられます。
  • 物体名の _ は表示時に半角スペースになります (red_bull → red bull)。物体名にスペースを直接書かないでください。
  • Image 列は任意です (ジェネレータは無視します)。

書き換えたら必ず検証する

./.venv/bin/python tools/check_data.py data
ok names                  table rows:  10   parsed:  10
ok rooms                  table rows:   4   parsed:   4
ok locations              table rows:  20   parsed:  20
ok object categories      table rows:   8   parsed:   8
   objects: 30   placement locations: 14   storage categories: 8

PROBLEMS: none

WARNINGS (generation still works)
  - the 'Object Category' column names ['foods'], ...

PROBLEMS は生成が壊れるもの、WARNINGS は知っておいた方がよいが 生成は動くものです。表の書式を崩すとこうなります。 

!! locations              table rows:  20   parsed:  11

PROBLEMS
  - locations: 20 row(s) in the markdown table but 11 parsed
      a location name may only contain letters, spaces and the '(p)' marker,
      and every row must end with '|'
      try: python3 tools/fix_data_format.py data

ok は「表に書いた行数」と「実際に読み込めた数」が一致しているという意味です。 !! が出たら必ず直してから本番に臨んでください。 黙って項目が消えたまま競技が始まるのが一番危険です。

仕上げに、5000 個生成してクラッシュしないかも確認しておくと安心です。

./run_cli.sh -g > /dev/null && echo OK
06

LLM による言い換え (任意)

コマンド生成自体は LLM 無しで動きます。 LLM が要るのは Rephrase / Rephrase ALL だけです。 接続先はジェネレータに内蔵されておらず、PC ごとに自分で指定します。 指定しないと https://api.openai.com に鍵無しで接続しにいき、押した瞬間に LLM ERROR になります。

その PC で使える LLM を探す

./.venv/bin/python tools/check_llm.py

引数なしで実行すると、そのPCのローカルポート (Ollama 11434 / vLLM 8000 / LM Studio 1234 など) を 順に叩き、見つかったサーバで実際に言い換えを 1 回実行します。 成功すればそのまま llm.conf に貼れる行が出ます。 

found Ollama on port 11434: gpsr-planner:latest, qwen3:8b, qwen2.5:7b-instruct

testing http://localhost:11434/v1/chat/completions  -a <set>  -m gpsr-planner:latest
  OK (4.0s for one command, 3 phrasings)
  in : Tell me what is the heaviest dish on the shelf
  out 0: What is the heaviest dish currently located on the shelf?
  out 1: Can you tell me which dish on the shelf is the heaviest?
  out 2: Which dish on the shelf weighs the most?

add this line to llm.conf:
  LLM_ARGS="--host localhost --port 11434 -a local -m gpsr-planner:latest"

失敗した場合も、原因と直し方 (モデル名が要る / thinking 非対応 / 鍵が違う / 誰も待ち受けていない) を具体的に出します。特定のサーバを直接試すこともできます。 

./.venv/bin/python tools/check_llm.py --host 192.168.0.5 --port 11434 -a local -m qwen3:8b
./.venv/bin/python tools/check_llm.py -u https://api.openai.com/v1/chat/completions -a sk-... -m gpt-5

llm.conf に書いておく

LLM 設定は PC ごとに違うので、リポジトリではなく llm.conf に置きます。

cp llm.conf.example llm.conf
# check_llm.py が出した LLM_ARGS の行に書き換える

# llm.conf
LLM_ARGS="--host localhost --port 11434 -a local -m qwen3:8b"

以降は今までどおり起動するだけで自動的に読み込まれます。

./run_gpsr_ui.sh
# → llm.conf: --host localhost --port 11434 -a local -m qwen3:8b

コマンドラインで LLM オプションを渡した場合はそちらが優先されます。 llm.conf は API キーを含みうるので .gitignore に入れてあります。

LLM が無い PC ではどうするか

状況やること
その PC に入れてよいcurl -fsSL https://ollama.com/install.sh | sh → ollama pull qwen3:8b → check_llm.py
チームの別 PC に LLM があるその PC で LLM を LAN に公開し、--host <その PC の IP> --port 11434 を指定。Ollama は既定で 127.0.0.1 のみなので OLLAMA_HOST=0.0.0.0 が必要
会場でネットが使えるOpenAI の鍵を使う: LLM_ARGS="-a sk-xxxxxxxx -m gpt-5"
用意できなくても競技はできます

Rephrase が使えないだけで、GPSR コマンドの生成・表示・ログ記録はすべて動きます。

サーバ別の注意点

サーバ注意
Ollama-m が必須 (無いと model is required)。さらに thinking 対応モデルが必要で、qwen2.5:7b-instruct は does not support thinking で失敗します。qwen3:8b と gpsr-planner:latest は動作確認済み
vLLM起動時にモデルが 1 つに決まるので -m は不要。付けないと「思考なし」指定でリクエストされます
OpenAI--url/--host を省くと自動的に api.openai.com + gpt-5 になります

-a (API キー) はローカルサーバでは中身を見られませんが、省略はできません。

速度

言い換えは 1 コマンドにつき 3 通り。qwen3:8b で 1 コマンド 10〜20 秒、gpsr-planner で 4 秒ほどでした。 Rephrase ALL は 3 コマンド分まとめて走るので、本番では必要なものだけ個別に Rephrase する方が安全です。LLM が Markdown の箇条書き以外を返すと上流のパーサが例外を投げ、 GUI に LLM ERROR と出ます。

07

困ったとき

症状原因と対処
Address already in use8080 番が使用中。--ui-port 9000 で変更するか、前回のプロセスを終了 (pkill -f gpsr_ui)
SyntaxErrorPython 3.12 未満で動かしている。.venv を使わず python3 で直接実行していないか確認
ModuleNotFoundError
(ROS を source した端末)		ROS の PYTHONPATH (Python 3.10) が仮想環境に混ざるため。run_*.sh は内部で unset PYTHONPATH しているので、必ずスクリプト経由で起動してください
家具や部屋が妙に少ないデータのフォーマット不備。tools/check_data.py で検証
is not a valid pathデータフォルダのパスが違う。-d に正しいパスを渡す (既定は ./data)
LLM ERRORほとんどの場合 LLM を指定せずに起動している (OpenAI に鍵無しで接続 → 401)。./.venv/bin/python tools/check_llm.py で使える接続先を探し、llm.conf に書いてください
フォルダを移動した.venv には絶対パスが埋め込まれています。移動先で ./setup.sh --recreate を実行してください (data/ と llm.conf はそのまま引き継がれます)
上流コマンドが即落ちるathome-generator-gpsr-ui は既定データパスが開発者の環境のままなので -d が必須。run_gpsr_ui.sh なら自動で付きます
別 PC からブラウザで開けないサーバは 0.0.0.0 で待ち受けています。ファイアウォールで 8080 番を許可してください

まとめて動作確認するには次を実行します。データ検証と、GUI のボタン操作 (生成 → Lock & Show) の自動テストが走ります。3 passed と出れば正常です。

./run_tests.sh

更新する

./setup.sh --latest
./run_tests.sh

上流の変更で GUI が壊れた場合は、setup.sh の GEN_COMMIT に書かれている 動作確認済みコミットに戻せます (引数なしの ./setup.sh がそれです)。
